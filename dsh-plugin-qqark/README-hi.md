# dsh-plugin-qqark

DeepSeek Harness (DSH) प्लगइन जो स्थानीय [QQ ग्रुप-फ़ाइल / चैट-वीडियो आर्काइवर](https://github.com/) को harness के अंदर ले आता है: एक साइडबार पैनल और चार read-only टूल जिन्हें agent बातचीत के दौरान सीधे कॉल कर सकता है।

> यह पैकेज दो-भाग वाली परियोजना का **प्लगइन वाला आधा हिस्सा** है। आर्काइवर (`main.py`, `qqark/`, शुद्ध Python 3.11 स्टैंडर्ड लाइब्रेरी) रिपॉज़िटरी की जड़ में है; प्लगइन उससे केवल `http://127.0.0.1:7801` पर बात करता है।

## Compatibility

| सतह | स्थिति |
|---|---|
| Harness | DeepSeek Harness `0.2.1-rc.5` और उसके बाद के `0.2.x` |
| Node | `^22.19.0 \|\| >=24.0.0` |
| प्लेटफ़ॉर्म | Web क्लाइंट; आर्काइवर वाला हिस्सा केवल Windows (`explorer /select,` का उपयोग) |

## What it does

आर्काइवर एक स्थायी प्रक्रिया है जो QQ ग्रुप फ़ाइलें और चैट वीडियो पकड़ती है। DSH बंद हो सकता है, पुनः आरंभ हो सकता है, या व्यस्त हो सकता है — कैप्चर उस पर निर्भर नहीं हो सकता। इसलिए बँटवारा जानबूझकर है: **काम आर्काइवर करता है, प्लगइन सिर्फ़ पुल है।**

### आर्किटेक्चर: पुल क्यों, सब कुछ प्लगइन में क्यों नहीं

- आर्काइवर को DSH बंद होने पर भी रिकॉर्ड करते रहना है। प्लगइन का जीवन harness प्रक्रिया जितना ही है, इसलिए कैप्चर लूप उसका नहीं हो सकता।
- प्लगइन आर्काइवर की स्थानीय HTTP API से बात करता है। कुछ डुप्लिकेट नहीं होता, Node से कोई डेटाबेस नहीं खोला जाता।
- **agent को दिए गए सभी टूल read-only हैं।** स्थिति बदलने वाली सभी क्रियाएँ (अभी स्कैन करें, विफल दोबारा आज़माएँ, ग्रुप चालू/बंद करें, QQ खाता बदलें) केवल उपयोगकर्ता द्वारा पैनल पर क्लिक करके होती हैं।

### टूल

| टूल | क्या लौटाता है |
|---|---|
| `qqark_status` | कनेक्शन स्थिति, लॉग-इन खाते, सेव डायरेक्टरी लिखने योग्य है या नहीं, क्यू काउंटर, कुल आँकड़े |
| `qqark_groups` | सभी ज्ञात ग्रुप, उनका कैप्चर स्विच, सदस्य संख्या, अंतिम स्कैन समय |
| `qqark_files` | डाउनलोड की गई फ़ाइलें, कीवर्ड / ग्रुप / श्रेणी / स्रोत से फ़िल्टर, स्थानीय पथ और ब्राउज़र में चलने योग्य मीडिया लिंक सहित |
| `qqark_tasks` | डाउनलोड क्यू और हाल के कार्य, विफलता के कारण सहित |

चारों शालीनता से गिरते हैं: आर्काइवर न चल रहा हो तो stack trace के बजाय `启动.bat` चलाने का संकेत लौटाते हैं।

### साइडबार पैनल

DSH web क्लाइंट में एक पैनल: स्थिति हेडर, प्रति-ग्रुप स्विच वाली ग्रुप सूची, फ़ाइल ब्राउज़र, डाउनलोड क्यू, लॉग व्यूअर, और एक «आर्काइव मोड» कार्ड जो आर्काइवर प्रक्रिया शुरू कर सकता है और NapCat को आर्काइव खाते व रोज़मर्रा के खाते के बीच बदल सकता है।

![साइडबार पैनल](../docs/screenshots/real-7801.png)

### जानने योग्य कुछ सुधार

- **`file_count` स्पष्ट रूप से भेजना ज़रूरी है।** NapCat के `get_group_root_files` / `get_group_files_by_folder` डिफ़ॉल्ट रूप से 50 आइटम लौटाते हैं, और आंतरिक पेजिनेशन लूप `r.length === n.fileCount` होते ही रुक जाता है। बड़ा ग्रुप चुपचाप कट जाता है, और वह कटाव अपरिवर्तनीय `gone` निर्णयों में बदल जाता था। समाधान: हमेशा `LIST_FILE_COUNT = 1000` भेजें।
- **`gone` एक अंतिम स्थिति है, `failed` से अलग।** कोई फ़ाइल तभी `gone` होती है जब तीनों बातें सही हों: उसका `file_id` रीफ़्रेश न हो पाए, स्कैन में कोई त्रुटि न हो, और पूरे पेड़ में वह नाम न मिले। आधी डायरेक्टरी पढ़े जाने पर कार्य पुनः-प्रयास योग्य `failed` ही रहता है।
- **Windows पर आर्काइवर को `detached: true` से कभी न चलाएँ।** मापी गई मैट्रिक्स में `detached: true` का हर संयोजन एक सेकंड के भीतर बंद हो गया; काम करने वाला तरीका `cmd /c start` है।
- **शुरू करने के बाद वापस पढ़ें।** `spawn` का सफल होना कुछ सिद्ध नहीं करता। सफलता बताने से पहले प्लगइन आर्काइवर के `/api/status` को तब तक पोल करता है जब तक वह वास्तव में उत्तर न दे।
- **होस्ट रूट में आगे `/` चाहिए; ब्राउज़र के `fetch` में नहीं।** GUI `<base href="./">` के अंतर्गत परोसा जाता है, इसलिए `fetch` में पूर्ण पथ प्लगइन रूट प्रीफ़िक्स को छोड़ देता है (DSH issue #1707)।
- **IPv6 होस्ट के कोष्ठक बने रहते हैं।** `new URL('ws://[::1]:6200/ws').hostname` कोष्ठक सहित `[::1]` देता है; तुलना या जाँच से पहले उन्हें हटाएँ।

## Install

```sh
pnpm pack
dsh plugin --profile <name> add ./dsh-plugin-qqark-<version>.tgz
dsh --profile <name> --dump-config | grep 'dsh-plugin-qqark'
```

bundle patch (`cordis.patch.yml`) `package.json#dsh.bundle.patch` के ज़रिए स्वतः लागू होता है। मशीन पर पूर्वापेक्षाएँ:

1. NapCat चल रहा हो और कोई QQ खाता लॉग-इन हो
2. आर्काइवर (`main.py`) चल रहा हो, `http://127.0.0.1:7801` उपलब्ध हो
3. प्लगइन सेटिंग्स में `grabAccount` / `quietAccount` भरे हों — ये जानबूझकर खाली आते हैं, क्योंकि डिफ़ॉल्ट किसी और के खाते की ओर चुपचाप इशारा करेगा

## Configuration

| कुंजी | प्रकार | डिफ़ॉल्ट | विवरण |
|---|---|---|---|
| `baseUrl` | string | `http://127.0.0.1:7801` | स्थानीय आर्काइवर का web पता |
| `timeoutMs` | natural | `8000` | प्रति-अनुरोध HTTP टाइमआउट (मिलीसेकंड) |
| `appDir` | string | `''` | आर्काइवर प्रोग्राम डायरेक्टरी (`启动.bat` जिसमें हो); खाली = स्वतः खोज |
| `grabAccount` | string | `''` | आर्काइविंग के लिए समर्पित QQ खाता; खाली हो तो आर्काइव मोड स्विच बंद |
| `quietAccount` | string | `''` | वापस लौटने वाला रोज़मर्रा का QQ खाता; खाली हो तो स्विच बंद |
| `napcatConfigDir` | string | `''` | NapCat की `napcat/config` डायरेक्टरी; खाली = स्वतः खोज |
| `wsPort` | natural | `6200` | NapCat के रिवर्स WebSocket के लिए आर्काइवर जो पोर्ट खोलता है |
| `astrbotPort` | natural | `6199` | वह बाहरी-बॉट पोर्ट जिसे आर्काइव मोड काट देता है |

कॉन्फ़िगरेशन `index.js` के Schemastery `Config` स्कीमा से सत्यापित होता है; कोई भी ट्यूनिंग मान कोड में हार्डकोड नहीं है। **जानबूझकर कोई डिफ़ॉल्ट QQ खाता नहीं है** — दोनों खाते भरे न होने तक प्लगइन आर्काइव मोड चालू करने से मना कर देता है और कारण बताता है।

## Development

```sh
pnpm install
pnpm test
```

कोई build चरण नहीं है: पैकेज सीधे शुद्ध ESM (`index.js`, `client.js`, `napcat.js`) देता है और harness उसे सीधे लोड करता है। प्रकाशन से पहले पैकेज अनुबंध जाँचें:

```sh
node <dsh-plugin-guide>/bin/dsh-plugin-dev.js check --cwd .
```

संरचना:

```
index.js          होस्ट आधा: config स्कीमा, HTTP पुल, होस्ट रूट, 4 टूल
client.js         web आधा: साइडबार पैनल कंपोनेंट (हाथ से लिखा h(), JSX नहीं)
napcat.js         NapCat खोज, लॉन्च, लॉगिन और OB11 क्लाइंट हॉट-रीलोड
cordis.patch.yml  bundle patch जो प्लगइन की पंक्ति जोड़ता है
locale/           zh.json, en.json
```
